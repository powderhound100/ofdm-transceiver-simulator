# ATSC 3.0 LDPC Decoder — Complete Implementation Plan

## Context

Build an open-source ATSC 3.0 LDPC decoder from scratch. The repo is empty. Three phases: Python reference prototype → Rust with SIMD → FPGA RTL (simulation-first, portable to hardware). Python runs first to generate test vectors; Rust and FPGA develop in parallel after.

## Known Complexity Issues and Mitigations

### Issue 1: Encoder complexity — GF(2) Gaussian elimination is infeasible for full codes
- **Problem:** The plan specifies GF(2) Gaussian elimination on H_parity (M×M matrix).
  For mock code (M=360) this is fine. For real ATSC 3.0 (M up to 56,160) it's O(M^3) — too slow.
- **Mitigation:** Use the **accumulator-based encoding** from the A/322 standard (same algorithm
  gr-atsc3 implements). For Type B: iterate over LUT rows, XOR info bits, then accumulate
  `p[j] ^= p[j-1]`. For Type A: two-phase accumulation with (q1, q2, m1, m2). GF(2) Gaussian
  elimination is only needed for the mock code (where it's fast) or not at all if we use
  accumulator encoding for mock code too.
- **Action:** P2 encoder supports both: accumulator encoding (default, required for ATSC 3.0)
  and GF(2) elimination (optional, for verification on small codes only).

### Issue 2: ATSC 3.0 has TWO code types — Type A (MET) and Type B (IRA)
- **Problem:** The plan assumes simple IRA structure for all rates. In reality:
  - **Type B (IRA):** Rates 6/15, 8/15–13/15. Single accumulator, parameter q. Simple.
  - **Type A (MET/Multi-Edge Type):** Rates 2/15–5/15, 7/15. Dual accumulators with
    parameters q1, q2, m1, m2. Two-phase encoding. Different H matrix structure.
- **Impact on decoder:** None — the decoder just sees H. The min-sum algorithm is identical
  for both types. The Tanner graph may have different degree distributions.
- **Impact on encoder:** Significant — must implement both encoding algorithms.
- **Impact on FPGA:** Minimal — base_matrix_rom stores the expanded H for whatever code type.
  The decoder architecture is unchanged.
- **Source:** gr-atsc3 `ldpc_bb_impl.cc` has both `ldpc_bf_type_a()` and `ldpc_bf_type_b()`.

### Issue 3: Base matrix format differs from our assumption
- **Problem:** Our plan assumes a standard QC-LDPC base matrix (2D grid of shift values, -1 for
  no edge). The gr-atsc3 tables use a **parity accumulator address list** format:
  `{count, addr1, addr2, ..., addrN}` per row, with circular shift parameter q.
- **Mitigation:** In `ldpc_code.py`, support BOTH formats:
  1. Standard QC base matrix (for mock code and other standards like 802.11n)
  2. ATSC 3.0 accumulator address list + q parameter (extracted from gr-atsc3)
  Both expand to the same H matrix / Tanner graph — the decoder doesn't care about the source format.

### Issue 4: Mock code base matrix not specified
- **Problem:** The plan says "10×18 base matrix with Z=36" but doesn't give actual entries.
  A random base matrix could yield a singular H_parity or poor error-floor performance.
- **Mitigation:** Use a **known-good standardized code** for the mock: IEEE 802.11n rate-1/2
  N=648 Z=27 (publicly available in the 802.11n spec, Table R1). Well-characterized waterfall,
  proven parity structure. Alternatively, extract one of the ATSC 3.0 short-frame codes
  (N=16200) from gr-atsc3 and use that — more representative of the target.
- **Decision:** Use 802.11n rate-1/2 N=648 Z=27 for initial development. Add ATSC 3.0
  short-frame (N=16200) and normal-frame (N=64800) as second and third test codes.

### Issue 5: Barrel shifter decomposition is Z=360-specific
- **Problem:** The 8×45 decomposition only works for Z=360. Mock code uses Z=27.
- **Mitigation:** Parameterize barrel_shifter.sv with Z as a parameter. For Z=27,
  use a simple log2(27)=5 stage shifter (trivial). For Z=360, use the 8×45 decomposition.
  The decomposition strategy is selected at synthesis time via `generate` blocks.

### Issue 6: Per-iteration test vectors scale badly for full codes
- **Problem:** For N=64800 at 50 iterations, storing all c2v/v2c per iteration would be
  ~200K edges × 50 iter × 4 bytes = ~40 MB per frame per SNR point. Manageable but large.
- **Mitigation:** For mock code (N=648): store all per-iteration data (small, ~100 KB total).
  For full ATSC 3.0 codes: store only iteration 0, iteration 1, and final iteration.
  This is sufficient for debugging — if iter 0 and 1 match, the rest will too.

### Issue 7: Alpha multiply doesn't need DSP slices
- **Problem:** Plan estimates 32 DSP slices for alpha scaling.
- **Reality:** α=0.75 = 3/4 = 1 - 1/4. Implemented as `x - (x >>> 2)` — just a subtractor
  and a 2-bit right shift. Zero DSP slices needed.
- **Updated resource estimate:** DSP usage drops from ~32 to ~0 for alpha scaling.
  DSPs only needed if we add configurable alpha (unlikely for initial implementation).

### Issue 8: Python decoder has O(degree²) inner loop
- **Problem:** `self.cn_to_vn[c].index(v)` in the VNU and CNU loops is O(degree) per call,
  making the overall complexity O(edges × degree) instead of O(edges).
- **Impact:** Python is the reference (correctness, not speed), so this is acceptable.
  But we must pre-compute the edge cross-reference maps to ensure the iteration order
  and edge numbering are well-defined for test vector comparison.
- **Mitigation:** In P1 (ldpc_code.py), pre-compute and export edge cross-reference maps
  alongside cn_to_vn and vn_to_cn. These maps are what Rust uses directly.

## Technical Trade-offs

### Rust vs C
Both compile via LLVM — identical machine code for SIMD intrinsics. Rust adds:
- Memory safety outside `unsafe` SIMD blocks (prevents buffer overflows in streaming pipeline)
- `cargo` + `criterion` + `clippy` = faster dev velocity than raw C/Make
- C ABI compatible for GNU Radio FFI via `extern "C"`
- No runtime/GC overhead — true zero-cost abstractions

**Decision: Rust.** No performance penalty vs C, better safety and tooling.

### Normalized Min-Sum vs Belief Propagation
- BP CNU: `product of tanh(v2c/2)` — needs LUTs or CORDIC in hardware
- NMS CNU: `min of |v2c|` + XOR of signs — just comparators and XOR gates
- Performance gap: ~0.2 dB, recovered by normalization factor α=0.75
- Hardware cost: NMS is 10x simpler, 3x less area, trivial in fixed-point

**Decision: NMS with α=0.75.** Standard in all commercial LDPC decoders.

### Flooding vs Layered Decoding (FPGA)
- Flooding: update ALL check nodes, then ALL variable nodes per iteration
- Layered: update one row-block of H at a time, immediately update variable beliefs
- Layered converges in ~half the iterations → 2x throughput
- Layered requires read-modify-write of variable beliefs (slightly more complex control)

**Decision: Flooding for Python/Rust (simpler, reference correctness). Layered for FPGA (throughput critical).**

### Min2 Architecture vs Full Edge Storage (FPGA)
- Full storage: 6 bits × ~200K edges = ~8 Mb → exceeds Arty A7 BRAM (4.9 Mb)
- Min2: store (min1, min2, argmin1, sign_product, individual signs) per check node
  - ~40 bits × 96 row-blocks × 360 ≈ 2 Mb → fits with margin
  - Saves 60%+ BRAM

**Decision: Min2 architecture.** Required to fit on Artix-7.

### Fixed-Point Quantization (FPGA)
- 6-bit LLR (1 sign + 5 magnitude, range -31 to +31)
- Proven < 0.1 dB loss vs floating-point in literature
- 5-bit would save area but costs ~0.3 dB — not worth it
- 7-bit marginal improvement, not worth the BRAM/routing cost

**Decision: 6-bit throughout.** Standard choice, well-characterized.

### Barrel Shifter Decomposition (FPGA)
- Z=360 full barrel shifter: log2(360)≈9 stages of 360-wide muxes — expensive
- Decompose: 360 = 8 × 45. Two smaller shifters in series:
  - Stage 1: shift by multiples of 45 (shift_val / 45), 8-way mux
  - Stage 2: shift by remainder (shift_val % 45), 45-way barrel shifter with 6 stages
- Saves ~30% LUTs vs monolithic shifter

**Decision: Decomposed 8×45 barrel shifter for Z=360. Simple log2 shifter for smaller Z (mock code Z=27). Selected at synthesis time via `generate`.**

### Alpha Scaling Without DSP
- α=0.75 = 3/4 = 1 - 1/4
- Implementation: `result = x - (x >>> 2)` — one subtractor + one 2-bit arithmetic right shift
- Zero DSP slices needed. Pure LUT logic.
- If configurable alpha is needed later, use a single DSP for multiply. Not needed for v1.

### Simulation Target
- Verilator: fast cycle-accurate C++ simulation, easy CI integration
- Icarus Verilog: slower but simpler setup, good for initial bring-up
- Both use standard SystemVerilog subset — portable to Vivado without changes
- Synthesis constraints (XDC) kept separate, not needed for sim

**Decision: Target Icarus for initial bring-up, Verilator for regression. RTL written to be synthesis-clean.**

## Subsystem I/O Specifications

Every subsystem has a well-defined input/output contract. When three implementations
(Python, Rust, FPGA) process the same input, they must produce the same output.

### Python Subsystem I/O

#### P1: ldpc_code.py — Code Definition

```
INPUT (two formats supported):

  Format A — Standard QC base matrix (for mock code / 802.11n / generic QC-LDPC):
    base_matrix: list[list[int]]    # mb×nb array, entries are -1 (no edge) or 0..Z-1 (shift)
    z: int                          # lifting factor (27 for 802.11n mock)

  Format B — ATSC 3.0 accumulator address table (from gr-atsc3):
    accum_table: list[list[int]]    # per-row address lists: [count, addr1, addr2, ...]
    q: int                          # circular shift parameter (or q1, q2 for Type A)
    n: int                          # codeword length (64800 or 16200)
    k: int                          # info bit length (from params.cc)
    code_type: str                  # "A" or "B"

INTERNAL DERIVATIONS:
  For Format A:
    mb = len(base_matrix)
    nb = len(base_matrix[0])
    N  = nb * z
    K  = (nb - mb) * z
    M  = N - K
  For Format B:
    N, K from input
    M  = N - K

OUTPUT:
  H: scipy.sparse.csc_matrix      # M×N binary parity-check matrix
  cn_to_vn: list[list[int]]       # length M, cn_to_vn[c] = sorted list of variable nodes connected to check c
  vn_to_cn: list[list[int]]       # length N, vn_to_cn[v] = sorted list of check nodes connected to variable v
  cn_edge_map: dict[(c,v) -> (cn_edge_idx, vn_edge_idx)]
                                   # pre-computed edge cross-references for decoder
                                   # eliminates O(degree) lookups in Python decoder

INVARIANTS:
  H.shape == (M, N)
  len(cn_to_vn[c]) == check node degree
  len(vn_to_cn[v]) == variable node degree
  Bidirectional consistency: for all c,j: cn_to_vn[c][j] in vn_to_cn[cn_to_vn[c][j]]
  Edge cross-refs: cn_edge_map[(c,v)] returns consistent indices into both adjacency lists
```

#### P2: encoder.py — LDPC Encoder (two methods)

```
INPUT:
  code: QcLdpcCode               # from P1
  info_bits: np.ndarray[uint8]    # length K, values {0, 1}

METHOD 1 — Accumulator encoding (default, works for all code sizes):
  For ATSC 3.0 Type B (IRA, rates 6/15, 8/15–13/15):
    For each row i of the accumulator address table:
      For each address addr in table[i]:
        For j in range(q):
          parity[(addr + j*q) % M] ^= info_bits[i + j * (K/360)]
    Then accumulate: parity[j] ^= parity[j-1] for j=1..M-1

  For ATSC 3.0 Type A (MET, rates 2/15–5/15, 7/15):
    Phase 1: m1 parity bits using table + q1
    Phase 2: m2 parity bits using aux_table + q2
    (See gr-atsc3 ldpc_bf_type_a() for reference)

METHOD 2 — GF(2) Gaussian elimination (mock code only, for verification):
  H_info:   H[:, :K]             # M×K submatrix
  H_parity: H[:, K:]             # M×M submatrix
  H_parity_inv: GF(2) inverse    # O(M^3), only feasible for M < ~1000
  parity_bits = H_parity_inv @ (H_info @ info_bits) mod 2

OUTPUT:
  codeword: np.ndarray[uint8]    # length N, values {0, 1}
     codeword[:K]  = info_bits
     codeword[K:]  = parity_bits

INVARIANT:
  H @ codeword % 2 == 0          # zero syndrome (ALWAYS, for any valid info_bits)
  Both methods produce IDENTICAL codewords for the same input (cross-check on mock code)
```

#### P3: channel.py — BPSK + AWGN + LLR

```
INPUT:
  codeword: np.ndarray[uint8]    # length N, values {0, 1} (from encoder)
  snr_db: float                  # signal-to-noise ratio in dB
  code_rate: float               # K/N (e.g., 0.444 for mock code)
  rng_seed: int                  # for reproducibility

INTERNAL:
  bpsk: np.ndarray[float64]      # length N, 0→+1.0, 1→-1.0
  sigma2 = 1.0 / (2.0 * code_rate * 10**(snr_db/10))
  noise: np.ndarray[float64]     # length N, drawn from N(0, sigma2)
  received = bpsk + noise        # noisy received signal

OUTPUT:
  channel_llr: np.ndarray[float64]   # length N
     channel_llr[i] = 2.0 * received[i] / sigma2
     positive → bit is probably 0
     negative → bit is probably 1
  sigma2: float                       # noise variance (needed for reference)

INVARIANT:
  At SNR >> 0 dB: sign(channel_llr[i]) == sign(bpsk[i]) for >99.9% of bits
  Mean of |channel_llr| increases with SNR
```

#### P4: decoder.py — Normalized Min-Sum Decoder

```
INPUT:
  code: QcLdpcCode               # from P1 (provides cn_to_vn, vn_to_cn)
  channel_llr: np.ndarray[float] # length N (from channel.py)
  alpha: float = 0.75            # normalization factor
  max_iter: int = 50             # maximum iterations

INTERNAL STATE (per decode call, reset each time):
  c2v[c][j]: float               # message from check c to its j-th connected variable node
                                  # initialized to 0.0
  v2c[v][i]: float               # message from variable v to its i-th connected check node

PER-ITERATION OUTPUTS (for test vector export):
  c2v_messages: list[list[float]] # all c2v after CNU, indexed [check_node][edge_within_check]
  v2c_messages: list[list[float]] # all v2c after VNU, indexed [var_node][edge_within_var]
  posterior: np.ndarray[float]    # length N, posterior[v] = channel_llr[v] + sum(c2v into v)
  hard_bits: np.ndarray[uint8]   # length N, hard_bits[v] = 1 if posterior[v] < 0 else 0
  syndrome: np.ndarray[uint8]    # length M, syndrome[c] = XOR of hard_bits for all v in cn_to_vn[c]

FINAL OUTPUT:
  decoded_bits: np.ndarray[uint8] # length N, values {0, 1} — the hard decision
  num_iterations: int             # iterations used (1..max_iter)
  converged: bool                 # True if syndrome was all-zero

INVARIANTS:
  If converged: H @ decoded_bits % 2 == 0
  c2v magnitudes bounded: |c2v[c][j]| <= alpha * max(|channel_llr|)  (no divergence)
  Extrinsic principle: v2c[v→c] does NOT depend on c2v[c→v] (subtracted out)
```

#### P5: test_ber.py — BER Simulation

```
INPUT:
  code: QcLdpcCode
  snr_range: list[float]          # e.g., [-3.0, -2.5, ..., 3.0]
  num_trials: int                 # frames per SNR point (100+)
  rng_seed: int                   # base seed (incremented per trial)

OUTPUT:
  results: list[dict] with fields:
    snr_db: float
    ber: float                    # bit errors in info bits / total info bits
    fer: float                    # frames with any error / total frames
    avg_iter: float               # mean iterations to convergence (or max_iter)
    num_trials: int

INVARIANT:
  BER is monotonically non-increasing with SNR (within statistical noise)
  FER >= 0 when BER > 0
  avg_iter decreases with SNR
```

#### P6: gen_test_vectors.py — Test Vector Export

```
INPUT:
  code: QcLdpcCode
  snr_points: [-2.0, -0.5, 2.0, inf]    # 4 operating points
  rng_seed: 42                           # fixed for reproducibility

OUTPUT FILES (in test_vectors/):
  base_matrix.json               # { "mb": int, "nb": int, "z": int, "entries": [[int]] }
  tanner_graph.json              # { "cn_to_vn": [[int]], "vn_to_cn": [[int]] }

  For each SNR point (e.g., snr_m0.5 for -0.5 dB):
    llr_snr_m0.5_f32.bin         # N float32 values, little-endian
    llr_snr_m0.5_6bit.hex        # N lines, each "XX" hex (2's complement 6-bit)
    decoded_snr_m0.5.bin         # N uint8 values (0 or 1)
    info_bits_snr_m0.5.bin       # K uint8 values (original info bits)
    num_iters_snr_m0.5.txt       # single integer: iterations to convergence

    iter_messages_snr_m0.5/      # per-iteration intermediate data
      c2v_iter00.hex             # M lines, each line = space-separated hex for each edge
      v2c_iter00.hex             # N lines, each line = space-separated hex for each edge
      posterior_iter00.hex       # N lines, each "XX" hex (6-bit quantized posterior)
      syndrome_iter00.txt        # "PASS" or "FAIL"
      ...

INVARIANT:
  Round-trip: reload each file, compare to in-memory values — exact match
  6-bit quantization: clip to [-31, +31], round to nearest integer
```

### Rust Subsystem I/O

#### R1: code.rs — Code + Tanner Graph

```
INPUT:
  base_matrix: &[i16]            # mb*nb row-major, -1 = no edge
  mb, nb, z: usize

OUTPUT:
  LdpcCode { n, k, m, z, mb, nb, base_matrix }
  TannerGraph {
    cn_to_vn_ptr: Vec<usize>     # CSR row pointers, length m+1
    cn_to_vn_idx: Vec<usize>     # CSR column indices, length = num_edges
    vn_to_cn_ptr: Vec<usize>     # CSR row pointers, length n+1
    vn_to_cn_idx: Vec<usize>     # CSR column indices, length = num_edges
    cn_edge_to_vn_edge: Vec<usize>  # for cn-side edge i, gives vn-side edge index
    vn_edge_to_cn_edge: Vec<usize>  # for vn-side edge i, gives cn-side edge index
    num_edges: usize
  }

INVARIANT:
  Must match Python's cn_to_vn and vn_to_cn lists exactly
  Cross-references: cn_to_vn_idx[e] == v implies vn_to_cn_idx[cn_edge_to_vn_edge[e]] maps back
```

#### R2: decoder.rs — Scalar Min-Sum Decoder

```
INPUT:
  graph: &TannerGraph
  channel_llr: &[f32]            # length N
  alpha: f32 = 0.75
  max_iter: usize = 50

INTERNAL (pre-allocated, reused across calls):
  c2v: Vec<f32>                  # length = num_edges, indexed by cn-side edge
  vn_sum: Vec<f32>               # length = N
  hard_bits: Vec<u8>             # length = N

OUTPUT:
  converged: bool
  iterations: usize
  decoded_bits: &[u8]            # length N, available via hard_bits slice

INVARIANT:
  For identical f32 inputs: decoded_bits must be bit-exact match with Python (f64 decoded,
  then compared at bit level — any float precision differences must not change decisions)
```

#### R3: simd.rs — AVX2 Check Node Update

```
INPUT (per check node row-block, Z check nodes at once):
  v2c_block: &[f32]             # Z * degree values, laid out as [edge0_z0..z359, edge1_z0..z359, ...]
  degree: usize                 # check node degree for this row-block

OUTPUT:
  c2v_block: &mut [f32]         # Z * degree values, same layout
     For each of Z check nodes:
       sign_product = XOR of signs of all incoming v2c
       min1, min2, argmin1 = two smallest magnitudes
       c2v[j] = alpha * (sign_product XOR sign[j]) * (min2 if j==argmin1 else min1)

INVARIANT:
  Bit-exact match with scalar CNU for identical f32 inputs
  (no approximate SIMD operations — only exact min, XOR, multiply)
```

### FPGA Subsystem I/O (port-level)

All signals use 6-bit signed 2's complement unless noted. Clock and reset omitted for brevity.

#### F1: barrel_shifter

```
PARAMETERS:
  Z = 360                        # number of elements
  W = 6                          # element width (bits)

PORTS:
  input  [W*Z-1:0]   data_in    # Z elements packed, each W bits
  input  [8:0]       shift_val  # 0..359 cyclic shift amount
  output [W*Z-1:0]   data_out   # data_in cyclically shifted right by shift_val

BEHAVIOR:
  data_out[i] = data_in[(i - shift_val) mod Z]   for i in 0..Z-1

LATENCY: 2 cycles (decomposed: stage1 coarse + stage2 fine)
```

#### F2: sign_xor_tree

```
PARAMETERS:
  WIDTH = 20                     # max check node degree

PORTS:
  input  [WIDTH-1:0]  signs_in  # sign bits of incoming messages (1=negative)
  input  [4:0]        degree    # actual degree (use only signs_in[0:degree-1])
  output              xor_out   # XOR of signs_in[0:degree-1]

LATENCY: 1 cycle (combinational with output register)
```

#### F3: min2_finder

```
PARAMETERS:
  WIDTH = 20                     # max check node degree
  MAG_BITS = 5                   # magnitude bits (unsigned, 0..31)

PORTS:
  input  [MAG_BITS*WIDTH-1:0]  mags_in    # packed magnitudes
  input  [4:0]                 degree      # actual number of valid inputs
  output [MAG_BITS-1:0]        min1_val    # smallest magnitude
  output [MAG_BITS-1:0]        min2_val    # second smallest magnitude
  output [4:0]                 argmin1     # index of min1 (0-based)
  output                       valid       # output valid strobe

LATENCY: 2 cycles (pipelined comparator tree)
```

#### F4: check_node_unit

```
PORTS:
  input  [W*Z-1:0]   v2c_in           # Z incoming v2c messages for current column block
  input  [8:0]        shift_val        # barrel shift for current column block
  input               first_col        # asserts on first column of this row-block (reset accumulators)
  input               last_col         # asserts on last column (trigger c2v output)
  output [W*Z-1:0]    c2v_out          # Z outgoing c2v messages for current column block
  output              c2v_valid        # c2v_out is valid

BEHAVIOR (across degree clock cycles, one per column block):
  Accumulates sign_product, min1, min2, argmin1 across all column blocks
  On last_col: computes c2v for each edge using min2 architecture
  c2v[j] = alpha * ext_sign * (min2 if j==argmin1 else min1)

LATENCY: degree + 2 cycles per row-block (degree column reads + 2 pipeline flush)
```

#### F5: variable_node_unit

```
PORTS:
  input  [W*Z-1:0]   channel_llr      # Z channel LLR values for current column block
  input  [W*Z-1:0]   c2v_in           # Z c2v messages for current check→variable edge
  input               first_check      # reset accumulator for this variable block
  output [W*Z-1:0]    v2c_out          # Z extrinsic v2c messages = posterior - c2v_in
  output [W*Z-1:0]    posterior_out    # Z posterior values (for hard decision)
  output              valid

BEHAVIOR:
  Accumulates: posterior[v] += c2v_in[v] (across all check nodes connected to v)
  On each input: v2c_out[v] = posterior[v] - c2v_in[v]  (extrinsic)
  All arithmetic saturates to [-31, +31]

LATENCY: 1 cycle
```

#### F6: message_ram

```
PARAMETERS:
  DEPTH = mb * Z = 360 * 10 = 3600  (for mock code)
  DATA_W = min1(5) + min2(5) + argmin1(5) + sign_product(1) + signs(20) = 36

PORTS:
  Port A (read):
    input  [log2(DEPTH)-1:0]  addr_a
    output [DATA_W-1:0]       rdata_a

  Port B (write):
    input  [log2(DEPTH)-1:0]  addr_b
    input  [DATA_W-1:0]       wdata_b
    input                     wen_b
```

#### F7: base_matrix_rom

```
PORTS:
  input  [6:0]   row_block     # 0..mb-1
  input  [4:0]   col_block     # 0..nb-1
  output [8:0]   shift_val     # 0..359 or 9'h1FF for -1 (no edge)
  output         has_edge      # 1 if entry >= 0

LATENCY: 1 cycle (registered ROM output)
```

#### F8: iteration_ctrl (FSM outputs)

```
PORTS:
  input               start           # begin decoding
  input               syndrome_pass   # from syndrome_checker
  output [5:0]        iter_count      # current iteration (0..max_iter-1)
  output              vnu_enable      # enable variable node update phase
  output              cnu_enable      # enable check node update phase
  output              syndrome_enable # enable syndrome check phase
  output              done            # decoding complete
  output              converged       # true if syndrome_pass caused termination
  output [6:0]        current_row     # current row-block being processed
  output [4:0]        current_col     # current column-block being processed

STATE MACHINE:
  IDLE → (start) → LOAD_LLR → VNU → CNU → SYNDROME_CHECK
    → if syndrome_pass: DONE (converged=1)
    → if iter_count == max_iter-1: DONE (converged=0)
    → else: VNU (next iteration)
```

#### F9: syndrome_checker

```
PORTS:
  input  [Z-1:0]     hard_bits_block  # Z hard-decision bits for current column
  input  [8:0]        shift_val       # barrel shift for this (row, col) block
  input               first_col       # reset accumulator for this row-block
  input               last_col        # trigger parity output
  input               last_row        # this is the final row-block
  output              all_checks_pass # asserts when ALL check nodes have even parity
  output              valid           # output is valid

BEHAVIOR:
  For each row-block: accumulate XOR of shifted hard_bits across columns
  After last_col of last_row: all_checks_pass = (all accumulated parities == 0)
```

#### F10: llr_input_buffer

```
PORTS:
  AXI-Stream slave (input from host):
    input  [W-1:0]    s_tdata
    input              s_tvalid
    output             s_tready
    input              s_tlast

  To decoder:
    output [W*Z-1:0]   llr_block_out   # Z LLRs for current column block
    input  [4:0]        col_addr        # which column block to read
    output              frame_ready     # a complete frame is buffered

BEHAVIOR:
  Accepts N LLR values via AXI-Stream, double-buffers into two frame slots.
  While decoder processes frame A, host can write frame B.
```

#### F11: output_buffer

```
PORTS:
  From decoder:
    input  [Z-1:0]     decoded_block   # Z decoded bits for current column block
    input  [4:0]        col_addr        # which column block
    input               write_en
    input               frame_done      # all columns written

  AXI-Stream master (output to host):
    output [7:0]        m_tdata         # bits packed into bytes
    output              m_tvalid
    input               m_tready
    output              m_tlast
```

#### F12: ldpc_top

```
PORTS:
  AXI-Stream slave (LLR input):
    input  [5:0]   s_tdata, s_tvalid, output s_tready, input s_tlast
  AXI-Stream master (decoded bit output):
    output [7:0]   m_tdata, m_tvalid, input m_tready, output m_tlast
  Control:
    input  [3:0]   code_rate_sel       # selects which base matrix to use
    input  [5:0]   max_iterations      # configurable max_iter
    output         busy                # decoding in progress
    output         done                # frame complete
    output [5:0]   iter_count_out      # iterations used
    output         converged_out       # syndrome passed

INTERNAL WIRING:
  llr_input_buffer → (llr_block) → variable_node_unit
  variable_node_unit → (v2c) → barrel_shifter → check_node_unit
  check_node_unit → (c2v) → barrel_shifter → variable_node_unit
  check_node_unit → (min2 data) → message_ram
  variable_node_unit → (hard bits) → syndrome_checker
  base_matrix_rom → (shift_val) → barrel_shifter, syndrome_checker
  iteration_ctrl → (enables, addresses) → all modules
  variable_node_unit → (decoded bits) → output_buffer
```

## Worktree Structure (3 parallel tracks after Python)

### Worktree 1: Python Reference (SEQUENTIAL — runs first)
All other worktrees depend on test vectors generated here.

Each task has **subsystem tests** (unit-level) and **integration gates** (must pass before next task).
After the full pipeline validates (P5), a **design review checkpoint** (P5b) captures
learnings and updates the plan for Rust/FPGA before proceeding.

| Task | File(s) | Description | Subsystem Test | Integration Gate |
|------|---------|-------------|----------------|------------------|
| P1 | ldpc_code.py | QC-LDPC code class, base matrix, circulant expansion to sparse H, Tanner graph extraction | Assert H shape (M×N), row weights match base matrix, column weights correct, H is sparse (density < 1%) | Generate H for mock code, verify rank(H) = M over GF(2), verify H has IRA dual-diagonal structure in parity portion |
| P2 | encoder.py | IRA encoder: GF(2) Gaussian elimination on H_parity, encode info→codeword | H@codeword%2=0 for 1000 random info vectors, encoder is deterministic (same input → same output) | Encode→check syndrome pipeline: random bits → encode → verify syndrome = 0 → flip 1 bit → verify syndrome ≠ 0 |
| P3 | channel.py | BPSK mod (0→+1, 1→-1), AWGN noise (σ²=1/(2R·10^(SNR/10))), LLR (2·r/σ²) | BPSK: verify ±1 output. AWGN: noise variance within 5% of target (statistical). LLR: sign matches transmitted bit at high SNR (>99.9%) | Full chain: encode → modulate → add noise → compute LLR → verify LLR signs match info bits at 10 dB SNR (should be >99%) |
| P4 | decoder.py | MinSumDecoder class, flooding NMS, α=0.75, max_iter=50, early termination | Noiseless: converge iter=1, exact bit match. Single-bit flip: converge in <5 iter. Message magnitudes bounded (no divergence). c2v messages have correct extrinsic property | **End-to-end mock decode**: encode random bits → BPSK → AWGN at 0 dB → LLR → decode → verify decoded bits == original info bits. | P5 | test_ber.py | BER sweep -3 to +3 dB, 100+ trials/point, print table | BER monotonically decreasing with SNR (within statistical noise). FER ≤ BER. Avg iterations decrease with SNR | **Full BER waterfall validation**: waterfall visible (~4 dB wide), BER < 1e-4 at +1 dB, BER > 1e-2 at -2 dB, curve shape matches theoretical LDPC behavior for rate ~0.44 |

### Test vector sets generated

For the mock code (N=648, Z=36, rate ~4/9), generate vectors at these SNR points:
- **High noise** (-2.0 dB): decoder struggles, may not converge — tests max_iter path
- **Waterfall** (-0.5 dB): partial convergence — tests typical operation
- **Clean** (+2.0 dB): converges in few iterations — tests early termination
- **Noiseless** (inf): converges in 1 iteration — basic sanity

Each set uses a **fixed random seed** so results are perfectly reproducible.
